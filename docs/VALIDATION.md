# 验证范围

## 软件回归

自动化测试覆盖论文库隔离、PDF 导入、API 配置与凭据保护、引用定位、问答状态分类、远程嵌入缓存、证据核验、代码扫描、源码绑定、严格输入校验和结果存储。代码转换回归包含数组、表格、文件路径、异步、方法调用以及审核的原生命令入口。

离线测试使用合成文件、代码夹具和模拟 API 响应，验证软件接口与状态处理。论文答案的事实准确性需要结合对应原文单独评估。

## MCP 验证

科学回归将实际 MCP 调用与原函数直接执行进行对照，包括正常输入、默认参数、数值边界、变化输入和错误输入。数组对照包含全部元素、置信区间及缺失值位置；R 对照包含完整原生对象、类、属性与原生文件。研究代码的统计假设与适用领域由上游论文、接口说明及来源记录定义。

验证覆盖所选函数及输入范围，完整实验复现需要另行设计。参数类型通过、调用成功与科学结论成立属于不同层次的验证。

## 论文问答对照

与原版 PaperQA 的对照使用相同 PDF、问题、远程问答及嵌入服务，分别控制文本切分和使用上游原生解析。题目在作答前按论文划分开发集与独立评估集，锁定源文件、问题和统计方法。

指标包括完整且有正确引用的回答、缺证据时明确拒答、可回答问题的误拒答、引用对应主张的准确性、执行错误、耗时和请求量。远程自动评分与回答生成分开，匿名提供答案和原文；有分歧或歧义的结果需要查阅原文复核。自动核验和评分均存在误判，不能代替领域专家判断。

对照仅涉及固定论文库中的 `Docs.aquery`，不包含上游自主文献搜索代理。动态 API 模型别名、论文抽样和 PDF 文本提取质量会影响可复现性与结论范围。

## 发行验收

发行检查包括独立目录安装、依赖完整性、网页与 CLI 操作、MCP 调用、文件校验值和包内容审查。论文问答的远程集成验证与离线软件测试分别记录。

[GitHub Actions](https://github.com/Liuenzecs/paper2agent-workbench/actions/workflows/verify.yml) 提供提交级检查状态。[最新发行版](https://github.com/Liuenzecs/paper2agent-workbench/releases/latest) 附带包内容清单、SHA256 和验证记录，可用于核对来源与验证范围。
